# ATS Rules

- Use standard headings such as `Professional Summary`, `Skills`, `Professional Experience`, `Projects`, `Education`, `Certifications`, and `Languages`, translated consistently for German documents.
- Use a simple single-column reading order unless the user provides a tested template.
- Avoid tables, text boxes, headers, footers, icons as labels, charts, and information conveyed only by color.
- Preserve selectable text in exported PDF files.
- Use canonical terminology from the advertisement only where a candidate claim supports it.
- Place high-priority supported terminology naturally in the summary, skills, and relevant experience.
- Bridge equivalent wording when accurate, for example `CI/CD-Pipelines für automatisierten Build und Deployment`.
- Do not stuff keywords, repeat technology lists in every role, add invisible text, or create unsupported skill sections.
- Do not claim an ATS score without running a named parser with a documented scoring method.
- Report coverage as counts by requirement priority and match class.
- Check spelling variants and abbreviations, but keep the version familiar to human readers.
